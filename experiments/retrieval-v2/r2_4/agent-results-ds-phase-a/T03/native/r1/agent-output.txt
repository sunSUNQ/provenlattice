## Document that describes it

**Primary: `docs/cn/consistent_hashing.md`.** (The English file `docs/en/consistent_hashing.md` is an untranslated stub that redirects to the Chinese version, so the Chinese document is the authoritative one.) The relevant section is **"# 虚拟节点个数" (Number of virtual nodes)**:

> 通过 -chash_num_replicas 可设置默认的虚拟节点个数，默认值为100。对于某些特殊场合，对虚拟节点个数有自定义的需求，可以通过将 *load_balancer_name* 加上参数 replicas=<num> 配置，如：
> ```c++
> channel.Init("http://...", "c_murmurhash:replicas=150", &options);
> ```

Translation: the default count of virtual nodes is set by `-chash_num_replicas` (default 100); the count can be customized per channel by appending `replicas=<num>` to *load_balancer_name*, e.g. `"c_murmurhash:replicas=150"`.

The design rationale for these `replicas` is in the same document's **"# 实现方式" (Implementation)** section (line 23): each server computes `m` hash values, dividing the 32-bit value space into `n*m` intervals; these extra hash values smooth the interval sizes and are called **virtual nodes** (虚拟节点); deleting a server merges its `m` intervals into neighbors, spreading its requests evenly — which is exactly the `_num_replicas`-per-server behavior the code implements.

A secondary in-repo citation is `docs/en/client.md:281` (and `docs/cn/client.md:280`), in the `c_murmurhash` section:

> Number of virtual nodes per server defaults to -chash_num_replicas(default 100) and can be overridden per channel: `c_murmurhash:replicas=300`.
