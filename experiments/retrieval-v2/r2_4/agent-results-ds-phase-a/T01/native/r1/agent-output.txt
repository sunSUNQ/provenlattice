## Relationship between doc and code

- **Name mapping**: the doc's `c_murmurhash_bl` string is the registration key in `global.cpp:416`; `LoadBalancer::New(params)` (cpp:498) clones the registered prototype and applies per-channel parameters.
- **Inheritance**: `ConsistentHashingBoundedLoadBalancer` derives from `ConsistentHashingLoadBalancer` (h:98), so it reuses the identical murmurhash ring — nodes built by `DefaultReplicaPolicy` with `MurmurHash32` (cpp:79-104), and the initial node lookup via `std::lower_bound` on `request_code` (cpp:552-556). This matches the doc's "哈希环与`c_murmurhash`完全相同".
- **Bounded-load extension**: it adds per-server `ServerLoad::inflight` counters in a doubly-buffered `FlatMap<SocketId, ServerLoad>` plus `_total_inflight` (h:112-129). `SelectServer` (cpp:525-602) computes `capacity = ceil(load_factor * (total_inflight+1) / server_count)` (cpp:546-551) and, instead of taking the hashed-to node directly, walks the ring clockwise to the first server with `inflight < capacity` (cpp:565-588) — the doc's "沿哈希环顺时针溢出到下一台有余量的服务器". `Feedback` (cpp:604-616) decrements the counters after the RPC completes.
- **Parameters**: `load_factor` comes from gflag `-chash_bounded_load_factor` (default 1.25, validated `> 1.0`, cpp:41-50) and is overridable per channel via `c_murmurhash_bl:load_factor=1.5` in `SetParameter` (cpp:509-523); `replicas` is delegated to the parent's `SetParameter` (cpp:418-425, backed by `-chash_num_replicas`, default 100) — exactly as the doc states.
