### The documented behavior
`docs/cn/client.md`, section `### c_murmurhash_bl` (lines 286–289): "带负载上限的一致性哈希" — Consistent Hashing with Bounded Loads (Mirrokni et al., CACM 2017). Same ring as `c_murmurhash`, but each server has capacity `ceil(load_factor * average_inflight)`; when the hashed-to server is full the request spills clockwise to the next server with spare capacity. `load_factor` defaults from `-chash_bounded_load_factor` (1.25, must be >1) and is overridable per channel via `c_murmurhash_bl:load_factor=1.5`; `replicas` behaves as in `c_murmurhash`.
