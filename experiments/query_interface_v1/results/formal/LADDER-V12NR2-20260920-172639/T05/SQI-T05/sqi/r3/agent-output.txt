## Documented behavior (docs/cn/client.md:286–288, section 负载均衡 / `c_murmurhash_bl`)

The section heading `### c_murmurhash_bl` describes a bounded-load consistent hash ring: identical to `c_murmurhash`, but each server additionally carries a capacity ceiling of `ceil(load_factor * average in-flight requests)`; when the hashed-to server is at capacity, the request overflows clockwise to the next server with spare capacity. The default factor comes from `-chash_bounded_load_factor` (1.25, must be > 1), overridable per channel via `c_murmurhash_bl:load_factor=1.5`; `replicas` behaves as in `c_murmurhash`.
