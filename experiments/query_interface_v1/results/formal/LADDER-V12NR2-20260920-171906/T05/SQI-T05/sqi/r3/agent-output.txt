## Answer

### The documented behavior
`docs/cn/client.md` §c_murmurhash_bl (lines 286–289) describes *Consistent Hashing with Bounded Loads* (Mirrokni et al., CACM 2017): the hash ring is identical to `c_murmurhash`, but each server carries a capacity of `ceil(load_factor * average in-flight)`; when the key's hashed server is at capacity, the request overflows clockwise to the next server with spare capacity; the factor defaults to `-chash_bounded_load_factor` (1.25, must be > 1) and can be overridden per channel via `c_murmurhash_bl:load_factor=1.5`; `replicas` behaves as in `c_murmurhash`.
