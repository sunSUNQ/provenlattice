## 2. V1.2-NR2 修复面（全部通用，无任务特判、无 oracle 变更）

C4-R3 归因表明残留失败不是实现缺陷，而是接口语义对 agent 不可见。NR2 以
四处通用机制补齐（不硬编码 required id、不特判 task id）：

1. **空结果指导（result_meta.empty_result_guidance）**：任何查询类型的
   空 envelope 附带确定性语义说明——锚点解析按调用类型限定
   （symbol.lookup 只匹配 code-symbol kinds；code.related / bundle.explain
   解析任意 node kind），同一字符串在不同调用类型下可解析性不同；在放弃
   一个锚点字符串前应换调用类型重试，而非重试语义等价形式。
   （`cf5e8c9`，`0124e72`）
2. **子集条款（usage_discipline[0] + prompt 镜像）**：同 anchor 更小预算
   重查只返回首 envelope 的证据子集（预算切片为确定性前缀，冻结 DB 上
   bundle/lookup 双路径实证）——换预算重查永不增加信息。
   （`013b26b`、`7d99a87`）
3. **knowledge-to-code 复合查询文档（arm prompt Call semantics）**：
   code.related 是 doc→code 复合查询（跨层链接 + 链接代码定义一次返回）；
   bundle.explain 只返回本地 bundle。文档化于 prompt 接口段。
   （`7f8737f`）
4. **会话级 usage_discipline 第三条规则**（与 prompt 镜像，随首个 envelope
   发射一次）。

修复有效性（对照 C4-R3）：T05.sqi 调用数 6-20/rep → **5/2/6**；T06 每-cell
恰好一次 bundle.explain；SMOKE 无回归。
