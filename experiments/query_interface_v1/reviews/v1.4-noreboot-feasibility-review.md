## 1. 结论

在不重启、不安装 WSL2/Docker/Windows Sandbox 的前提下，通过
**Sanitized Runtime Copy + 整 checkout 可继承 deny-read ACL + deny-write +
disposable repo + leakage scanner**，实现了：

- 正式会话 agent 对**整个 provenlattice checkout 与历史 transcript store**
  的读取被 NTFS 内核拒绝（11/11 探针 + agent 上下文 8/8 探针 ACCESS_DENIED）；
- sanitized SQI bridge、frozen DB 副本、disposable repo 上
  T01.sqi / T05.sqi 代表性会话完整跑通；
- 会话后全量恢复（HEAD / 工作树 / DB hash 不变）。

这是 **experiment-artifact isolation（有限敏感根）**，不是 full OS-namespace
isolation —— 宿主任意其他路径对同用户进程仍可见（已在 evidence 中文档化）。

## 3. 平台发现（pre-flight + 执行期，已固化进 evidence）

- **P1**：`icacls /deny user:(R) /T` 无法传播 —— deny 根目录后 icacls 自身
  失去枚举权，静默跳过全部子项。（这解释了 V1.4 证据
  `gate-evidence-v1.4.json` 的 `ground_truth_denied: 0` 与 review 文档
  "3/3 denied" 的矛盾 —— review 的deny 生效声明不成立。）
- **P2**：正确非管理员模式 = 根上**单个可继承 ACE**：
  `icacls <root> /deny user:(OI)(CI)R`；`/remove:d user` 一步恢复。
- **P3**：deny (R) 不阻止在被拒目录内新建文件（runtime/agent 写不受影响）。
- **P4**：claude CLI 2.1.270 对**脚本文件执行**（`python x.py`）在
  (a) system prompt 含安全约束句、(b) deny 窗口激活 时强制 approval；
  模块形式（`python -m <module>`，bridge 同形态）免疫；同样句子放 user turn 无影响。
- **P5**：deny 窗口下，对抗性措辞的 system prompt（"isolation verification
  probe ..."）也会触发模块执行的 gating；中性 ARM 风格措辞放行。
- **P6**：`v14_sandbox.build_disposable_copy` 的 robocopy 参数顺序缺陷
  （`XD .git` 无斜杠被解析为文件名过滤器）→ 复制结果为空。
  V1.4 I5 的 "disposable copy writable" 判定不受影响（空目录也可写），
  但任何依赖 copy 内容的用法都会退化。本 runner 自带修正版并校验文件数。
- **P7**（2026-09-18 amendment 期发现）：generic-read deny `(R)` 会间歇性
  拒绝 icacls 自身的 READ_CONTROL，使 `/remove:d` rc=5 失败且不可自愈
  （5 轮实测出现）。读 deny 冻结为 `(RD)`（read data / list directory）：
  保护语义相同（内容读+目录枚举被拒、元数据可见），恢复通道 5/5 稳定。
  本 review 首轮 FEASIBLE 证据使用 `(R)`；确认重跑（amendment seal 前）
  使用最终 `(RD)` 机制。

## 4. 威胁模型边界（须随 profile 声明）

- **内核拒绝**：整个 checkout、`%USERPROFILE%\.claude\projects`、
  frozen originals 写入。
- **文档化 out-of-scope**：宿主其余路径（同用户可读）、原 benchmark DB
  内容（与 runtime 字节副本相同，是被授权的 bridge 基质）、workspace 父目录列表。
- 不声称：agent 在 OS 命名空间层面只能看到 sandbox 内文件。
