## 1. 设计原则

- `tests/test_v14_smoke_harness.py` 是**薄层 release 门禁**,不是功能套件:深度覆盖仍由既有 qualification 套件承担,本文件只验证 release 面向的基本面。
- 复用既有能力,不复制测试:MCP server 路径/契约/fixture 直接 `import test_mcp_defect_e2e` 复用,不重复实现。
- 不改变默认行为:零产品代码改动;任何检查失败均以显式 `AssertionError`(含 stdout/stderr 上下文)fail loudly,无静默降级。

## 4. 运行中捕获并修正的问题

初版 harness 的 index/query 流程在 `index` 后直接发起 defect 查询,得到 `status: stale, reason: upstream_not_built`(missing: events/sparse_cfg/sparse_dfg)。这**不是产品缺陷**,而是正确的 fail-closed 契约:基础图谱不含 defect 上游分析器。已将流程修正为完整的 `index → analyze --features defect → defect` 三步。该事件同时验证了两点:

1. fail-closed 契约在全新 CLI 流程下真实生效(未静默返回空结果);
2. smoke harness 对 release 基本面回归具有实际捕获能力。

## 5. Known limitations

1. `test_mcp_defect_e2e` 的 unclosed pipe ResourceWarning 同样适用于本 harness 的 MCP 探针(非失败项,见 P1 报告)。
2. `test_fresh_install_path` 验证的是"当前解释器环境中的 distribution 解析",不在测试内新建 venv(全新 venv 安装验证由 P3 报告以真实 wheel 完成)。
3. Linux 行为未在本地验证,待 P1 CI Linux job 远程 Run 闭环。
