## 2. MCP stdio client 验证方式

- 以子进程启动真实 MCP server(`sys.executable` + `PYTHONPATH=src`),通过 stdin/stdout 以 JSON-RPC 2.0 逐行通信,按响应 `id` 匹配请求。
- `setUpClass` 在临时目录中对 C 缺陷 fixture(`malloc`/`free` 双路径源码)执行 `full_index` + `analyze_scope`,建立真实图谱数据库,非 mock。
- 8 类 query 全量覆盖:`resource_lifetime` / `lock_order` / `race_condition` / `null_flow` / `use_after_free` / `double_free` / `taint_path` / `error_handling`。
- 断言:响应含 `result` 且 `content` 非空;`content[0].text` 为合法 JSON;`status == "available"`;`grade` 字段存在(commit `36c2f94` 记录中同时核验 grade/level/provenance 字段)。
- stale 场景:指向不存在的 `--database` 路径,断言 fail-closed(返回 JSON 时 `status != "available"`,或输出含错误信息)。
