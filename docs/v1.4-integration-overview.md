# ProvenLattice V1.4 Integration Overview

> 版本:V1.4(2026-10-13)
> 本文档为独立阅读的技术报告,覆盖 V1.3 → V1.4 的选择性整合全过程。

## 1. 整合背景与目标

ProvenLattice V1.3 是一个面向 Code Agent 的工程证据基础设施。同事在独立 fork 上开发了缺陷导向的稀疏语义分析管线(PR #1)。两条线共享 Foundation Graph,但分析目标、抽象粒度和实现路径不同。

V1.4 的目标是:在不破坏 Foundation Graph 的前提下,将 PR #1 的缺陷检测能力选择性迁移为按需调用的 Code Inspection 服务,统一为 **Shared Foundation + Unified Analysis Engine + Dual Task Domains** 架构。

## 6. 选择性整合的技术理由

**为什么不直接合并 PR #1?**

PR #1 的 declarations 重构改变了 L1 符号集合(同一语料上 Function -86%)。这意味着 RQ1 图保真度资格(precision 0.931)的口径失效,需要重新资格化。此外,事件提取嵌入 index 使索引成本 +157%,违反 Gold Target V2 原则 5(低成本默认)。

**为什么不放弃 PR #1?**

PR #1 的缺陷查询、Evidence Bundle 和三态可达性是 Gold Target V2 Code Inspection 能力域的核心交付,main 完全没有等价物。

**为什么选择按需触发?**

将事件提取从 index 分离后,普通用户成本不变;需要检测的用户通过 `analyze --features defect` 显式触发上游链。这符合 Capability × Scope 双维控制原则。
